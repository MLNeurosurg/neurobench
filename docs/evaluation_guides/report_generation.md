# Report generation evaluation

## Overview

The report generation evaluator is for all tasks in `neurobench_data/visual_question_answering/report_generation`. It compares a pair of candidate reports against a reference radiologist report for coverage of clinically significant neuroradiological findings and avoidance of unsupported content.

Results report win, tie, and loss rates for each model pair across retained questions.

> [!NOTE]
> This is a *pairwise-preference* metric, so you must provide reports from at least two models. Reports generated by [Neuro-VL](https://github.com/MLNeurosurg/neuro-vl) are included with the downloaded Hugging Face dataset (see the [download instructions](../data.md)), located under `neurobench_data/neuro_vl_assets/`.

## Inputs

Choose a CSV from [the report-generation question bank](https://huggingface.co/datasets/mlinslab/neurobench/tree/main/visual_question_answering/report_generation/) and add response columns for at least two models. See [Prepare responses](../../README.md#3-prepare-responses) for response formatting.

Paths below are relative to `visual_question_answering/report_generation/`. The two CSVs contain 2,661 studies in total, with one question per study.

| Cohort | Question CSV | Studies |
|---|---|---:|
| MR-RATE | `mr_rate/report.csv` | 1,278 |
| CTRG-Brain-263K | `ctrg_brain_263k/report.csv` | 1,383 |

Below, a "question" refers to one report-generation row in the input CSV. The default prompt is: "Write a comprehensive radiology report based on the provided imaging, organized into FINDINGS and IMPRESSION sections."

| Column | Purpose |
|---|---|
| `answer` | Reference radiologist report used by the judge |
| `dataset`, `patient`, `study` | Default identifiers for a unique study |
| Your model response columns | Candidate reports to compare |

To compare against Neuro-VL, join the baseline reports from `neuro_vl_assets/` to your question CSV on `dataset`, `patient`, and `study`, reading these identifiers as strings. Keep the original reference `answer` unchanged and add `neuro-vl answer` alongside your model's response column. Select the baseline with `--candidate_answer "neuro-vl answer" "Neuro-VL"` in addition to your model's `--candidate_answer` argument.

To compare report-generation prompt formats, use the same studies in separate CSVs and runs, with a different output directory for each format. If a study has multiple questions in one CSV, include a distinguishing column in `--id_columns`. Each row counts as a separate question in the same summary. Use `--reference_answer_column COLUMN` when the reference is stored under another name.

## Run

Complete the [local GPT-OSS setup](../llm_judge_setup.md#setup) first. Keep the server running at `localhost:8000`.

For example, prepare `reports_with_outputs.csv` with the original benchmark columns and two generated-report columns named `model_a_output` and `model_b_output`. Replace the CSV path below with your own:

```bash
neurobench evaluate \
  --task report_generation \
  --csv /path/to/reports_with_outputs.csv \
  --candidate_answer model_a_output ModelAName \
  --candidate_answer model_b_output ModelBName \
  --output_dir results/reports
```

Here, `model_a_output` and `model_b_output` are CSV column names; `ModelAName` and `ModelBName` are the display names used in results. The reference report comes from `answer`. No API key is needed for the local setup.

Use a new or empty output directory for every run, including reruns after interruption or failure.

Repeat `--candidate_answer` for more models. `--n_evals_per_pair` sets judgments per pair; the default is four. Even counts balance candidate presentation order. `--prompt_path PATH` selects an alternative rubric.

## Scoring

Each row of `summary.csv` compares `candidate_1_model` with `candidate_2_model`. A win for one model is a loss for the other. The figure in `results.png` shows the same three outcomes as percentages:

| Summary columns | Meaning |
|---|---|
| `candidate_1_wins`, `candidate_1_win_rate` | Questions won by the first model, as a count and a proportion |
| `ties`, `tie_rate` | Questions where neither model is preferred, as a count and a proportion |
| `candidate_2_wins`, `candidate_2_win_rate` | Questions won by the second model, as a count and a proportion |
| `n_questions`, `n_complete`, `n_excluded` | Total input questions, questions included in the comparison, and questions excluded |

For example, rates of 0.60, 0.25, and 0.15 mean the first model wins 60% of scored questions, 25% are tied, and the second model wins 15%.

Each question is included only when every candidate model has a nonblank report and every model pair has successful judge votes. Otherwise, the question is excluded from all pairwise summaries in that run. See the [evaluation auditing guide](auditing.md) for additional details.

### Judgement process

The judge receives the reference report and anonymous candidates A and B. It assesses clinically significant omissions, contradictions, and unsupported findings using the [report rubric](../../neurobench/evaluation/report_generation/prompts/report.txt). Each judgment returns an explanation in `rationale` and a `winner` of `A`, `B`, or `tie`.

By default, **each pair of nonblank reports for a question is judged four times**, using seeds 42–45 and alternating A/B positions for each report. Votes are then aggregated into the final result:

- If `tie` receives more votes than either model, the pair is a tie.
- Otherwise, the model with more votes wins. Equal model vote counts produce a tie.

For example, ModelA=2/ModelB=0/tie=2 means ModelA wins. ModelA=1/ModelB=1/tie=2 and ModelA=2/ModelB=2/tie=0 both produce a tie. The resulting pairwise outcomes are counted once per question to calculate the summary rates.

## Outputs

Start with `results.png` and `summary.csv`. You may look at the other files to inspect individual comparisons.

| File | What it contains |
|---|---|
| `results.png` | Win/tie/loss percentages for each model pair on the retained-question cohort, with retained/total counts |
| `summary.csv` | One row per model pair, with win/tie/loss counts, rates, and question coverage |
| `results.csv` | Original input rows with question identifiers, evaluation status, and any error |
| `pairwise.csv` | Vote counts and final outcomes for each question/model pair, including whether it contributes to the summary |
| `judge_votes.csv` | One row per planned judgment, with vote/seed, A/B model assignments, parsed winner and rationale, status, error, and raw response |
| `llm_job/responses.jsonl` | Individual judge responses, including their explanations |
| `evaluation_issues.csv` | Information on excluded responses; see the [evaluation auditing guide](auditing.md) for details |
